Case Study

Docs Quality Assurance with Docs-as-Code

A research-backed documentation quality process that used Docs-as-Code and DevOps workflows to improve accuracy, collaboration, and delivery speed.

Documentation quality improved when docs became part of the product workflow.

The project introduced a centralized Azure DevOps workflow where planning, authoring, review, and publishing could be tracked and improved together.

Type
Master's Research Project
Role
Researcher & Process Designer
Published
April 23, 2025

Context

During my master's program in technical communication, I discovered the Docs-as-Code approach during a final internship. At the time, the company's product documentation was fragmented, inconsistent, and missing a formal review or publishing workflow.

There was no clear ownership model, documentation quality varied across teams, and product changes were not consistently reflected in user-facing help content. I used this as both a research opportunity and a real process-design challenge.

Key Improvements

  • Centralized Docs-as-Code workflow in Azure DevOps
  • Ticketing linked to product backlog items
  • SME collaboration through wikis and pull requests
  • Git and Markdown version control for documentation
  • Reusable templates and a consistent style guide
  • Documentation updates aligned with product releases

Process

01

Research & Discovery

I conducted unstructured interviews with product managers and community leads to identify root causes behind documentation quality issues.

02

Feasibility Analysis

I assessed documentation workflows and tools. Azure DevOps emerged as the best fit because it connected documentation work to product development.

03

Process Modeling

I designed a quality model built on three principles: centralization, collaboration, and continuous delivery.

04

Implementation & Review

I configured wikis, ticketing, repositories, pull requests, review checkpoints, templates, and Markdown standards.

My Role

  • Conducted qualitative research with product and community managers
  • Identified duplication, missing version control, and style inconsistencies
  • Designed a documentation QA model around three core principles
  • Implemented the workflow in Azure DevOps with Markdown-based documentation
  • Created training and documentation to support team adoption

Approach & Solution

The process was inspired by DevOps principles but adapted for technical documentation. Centralization placed planning, writing, review, and publishing in one system. Collaboration brought product managers and SMEs into pre-creation Q&A, ticketing, and post-creation pull request reviews.

Continuous delivery aligned documentation with product releases, reducing the risk of outdated or fragmented help content.

Outcome

The documentation process became the company's new standard. Version control reduced fragmentation, ticketing made documentation needs visible beside feature development, and pull requests introduced traceable review cycles with validation checkpoints.

The project also confirmed that documentation quality is deeply tied to process design: good technical content needs clear ownership, collaborative review, and a workflow that moves with the product.

What I Learned

Docs-as-Code is more than a production method. It is a mindset that brings transparency, efficiency, and credibility to technical content creation.
