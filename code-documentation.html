Case Study

Revamping Code Documentation

A modernization project for SCADA Basic instruction documentation, inspired by API documentation patterns and designed for future code-driven workflows.

Flat instruction tables became a structured, code-friendly documentation model.

The project redesigned legacy SCADA Basic documentation into a more readable, collapsible format and explored a workflow for generating styled Flare topics from Markdown.

Client
PcVue
Type
Code Documentation
Role
UX Engineer & Information Architect
Published
April 23, 2025

Context

SCADA Basic language documentation was historically presented in flat HTML tables with limited structure and visual hierarchy. The documentation was hard to navigate, visually outdated, and disconnected from the evolving SCADA Basic editor.

Developers and users needed a cleaner, more interactive format that could support future improvements such as IntelliSense and in-app help.

Skills & Expertise

  • Information architecture
  • Developer documentation design
  • MadCap Flare
  • HTML5, CSS & jQuery
  • Markdown workflow prototyping

Process

01

Design Exploration

I modeled a new visual format after Swagger UI, focusing on collapsibility, clarity, and code-centric presentation.

02

Flare Restructuring

I converted legacy content into HTML5-compatible Flare topics using custom CSS, snippets, headings, code blocks, and disclosure elements.

03

Workflow Prototyping

I designed a future workflow where Markdown generated by developers could be transformed into Flare-compatible HTML.

04

Future Integration

I considered paths for preserving accuracy and styling consistency as the editor evolved toward IntelliSense and in-app help.

My Role

I initiated and led the redesign of the SCADA Basic instruction display format. I created a MadCap Flare presentation system inspired by Swagger UI and laid the groundwork for a future-proof Markdown-to-Flare workflow.

Solution

Each instruction could be presented through consistent headings, code blocks, dynamic disclosure elements, and a clearer hierarchy. Two workflow paths were explored: Markdown with mapped classes/selectors, or raw Markdown transformed by a preprocessing script before Flare import.

Outcomes

The redesign established a reusable model for SCADA Basic documentation:

  • Created structured instruction layouts with collapsible sections and code blocks.
  • Built reusable styling and topic components in MadCap Flare.
  • Prototyped a Markdown-to-Flare workflow for future developer contributions.
  • Left a foundation for continued modernization; the project ended before full implementation.

What Changed

  • More readable instruction structure
  • Cleaner code-centric presentation
  • Reusable styling inside Flare
  • A path toward developer-generated documentation
